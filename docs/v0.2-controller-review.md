# v0.2 Controller Review

Status: **controller review only — not an independent final review**.

Branch: `dev/performance-banner-designer-v0.2`

This document records controller-owned architecture review findings that were found and reconciled while hardening the release candidate. It must not be presented as the independent final repository review required by the release gate.

## Review scope

Reviewed against the intended production contract:

`research → category → idea/presentation/emotion → visual character → Style Intelligence → attention/type → lighting intent → art direction → assets → representative → campaign design system → preproduction freeze → creative freeze → exact render jobs → Google technical preflight → visual review → Google policy preflight → final readiness`

## Reconciled architecture findings

### 1. Meaning and style were originally under-specified

The earlier pipeline could move from category research to art direction without a stable semantic idea architecture. The user-supplied visual methodology exposed this gap.

Reconciliation:
- explicit `IDEA_ARCHITECTURE`;
- presentation mode;
- emotional target;
- visual-character signature;
- focus budget;
- Creative Chaos Audit;
- forbidden-visual layers.

### 2. Lighting could become decorative rather than semantic

Reconciliation:
- `LIGHTING_INTENT` now derives from idea, presentation, emotion, visual character/style and primary AOI;
- scene-lighting and composition-lighting modes are explicit;
- real product/UI evidence can make scene lighting `NOT_APPLICABLE`;
- campaign lighting may narrow but not expand approved lighting primitives.

### 3. Contemporary style selection needed a controller-level strategy

A model choosing fashionable style labels directly is too weak and can produce category-inappropriate or trend-driven work.

Reconciliation:
- September 2026 Style Intelligence library;
- foundation grammar vs contemporary overlay separation;
- execution language, attention, typography, lighting and format-resilience dimensions;
- currentness weight capped at 5%;
- stale-currentness disable;
- three decision-support lanes;
- wildcard disruption-corridor constraint;
- exact recommendation/component SHA binding through art direction and campaign system.

### 4. Typography needed runtime truth, not a fashion list

Reconciliation:
- type-role profiles rather than fixed font prescriptions;
- brand font precedence;
- font examples are candidates only;
- production requires license, actual local file, language/script, Cyrillic/Belarusian glyph, weight/width and exact-raster verification.

### 5. Real acceptance showed commercial/brand drift

`REAL-02` demonstrated that even a stronger art direction could silently change CTA wording and leave brand identity ambiguous.

Reconciliation:
- `commercial_lock` with approved CTA allowlist;
- `brand_identity_lock`;
- real-asset requirements;
- `NEEDS_ASSET` fail-closed behavior;
- creative-freeze enforcement.

### 6. Google technical validation was not Google policy validation

This became an explicit architectural gap after reviewing current Google Advertising Policies on 2026-09-07.

A file can have valid dimensions/bytes and still be disapproved because of misleading design, unreadable imagery, misrepresentation, unavailable offers, destination problems, trademark context, restricted vertical rules or other policy issues.

Reconciliation:
- `references/google-ads-policy-preflight.md`;
- dated `config/google-ads-policy-snapshot.json` with freshness semantics;
- exact-artifact `google-policy-context` and report schemas;
- fail-closed `validate_google_policy.py`;
- pack-level `aggregate_google_policy_reports.py`;
- final `assess_google_ready.py`;
- no-approval-guarantee semantics.

The policy system separates:
- creative policy;
- destination policy;
- trademark context;
- vertical certification;
- targeting policy;
- account/Google enforcement beyond local proof.

### 7. Policy visual judgments must not be fabricated by deterministic code

The policy validator intentionally does not use OCR or infer every semantic issue from pixels. It requires a `GOOGLE_POLICY_REVIEWER` judgment bound to the exact artifact SHA for misleading-design/image-quality/content checks.

Deterministic code handles what it can actually prove, such as:
- file existence/SHA;
- dimensions/decoded format;
- PNG transparency;
- policy snapshot freshness;
- structured claim/destination/trademark/vertical evidence consistency.

This keeps evidence boundaries explicit.

### 8. Landing page is part of Google readiness

The banner alone cannot prove policy readiness.

Local PASS requires structured destination evidence for working URL, relevance, offer/CTA availability, advertiser identity, crawlability/accessibility state and original/useful content. `UNKNOWN` material destination evidence blocks a Google-ready claim.

### 9. Trademark and affiliation need contextual treatment

Third-party product names are not treated as universally forbidden or universally safe.

For reseller/integrator campaigns, the system requires explicit trademark review status and verified affiliation when official/partner claims are made. Unresolved use returns `TRADEMARK_REVIEW_REQUIRED` rather than invented authorization.

### 10. Final Google-ready wording needed a dedicated gate

Reconciliation:
- ordinary design readiness and Google policy readiness remain separate;
- pack policy aggregation requires every final artifact report to match exact output SHA;
- only `GOOGLE_POLICY_PREFLIGHT_PASS` can feed final local clearance;
- `GOOGLE_READY_PRECHECK_PASS` still carries `google_upload_approval_guaranteed=false`.

## Still not independently proven

The following remain release blockers unless explicitly accepted as degraded rigor:
- fresh visual-review calibration on all six hidden-key cases;
- genuinely independent final repository/PR review;
- real Work acceptance of the full latest MITGROUP flow;
- real exact-artifact Google policy preflight using the actual MITGROUP landing page, advertiser/trademark relationship and final banner pack.

The controller must not convert green deterministic CI into a claim of actual Google approval or full independent design validation.
