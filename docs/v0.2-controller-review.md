# v0.2 Controller Review

This is a **controller-level** repository review, not a genuinely independent external review.

## Review objective

Check whether the production contracts actually enforce the promises made by `SKILL.md`, especially after real Work failures and the new user-supplied visual methodology.

## Current architecture reviewed

Canonical static path:

`intake → run freeze → references → competitive research → category map → idea architecture → presentation mode → emotional target → visual character → focus/forbidden/chaos audit → commercial/brand locks → lighting intent → written art direction → asset readiness → optional hero generation spec → one high-fidelity representative → representative approval → campaign design system → preproduction freeze → creative freeze → job materialization → deterministic rendering → Google preflight → manifest → design QA → independent banner reviews → pack review → readiness`

## Important hardening findings already resolved

### 1. Art direction was initially too close to style-only selection

Resolved by adding:
- `IDEA_ARCHITECTURE`;
- presentation mode;
- emotional target;
- visual-character signature;
- focus budget;
- Creative Chaos Audit.

A direction now has to inherit semantic identity rather than merely choose typography/color/hero treatment.

### 2. Lighting could previously be chosen as an isolated visual treatment

Resolved by adding `LIGHTING_INTENT` downstream of:

`idea → presentation → emotion → character → AOI`.

Scene/composition lighting have explicit applicability modes, candidate scheme/primitives, copy-safe and focal-priority policies. Art direction must inherit the same lighting-intent ID.

### 3. Real product/UI truth must outrank visual spectacle

Resolved by explicit asset readiness and lighting rules:
- missing required real UI/logo returns `NEEDS_ASSET`;
- fake generated UI cannot satisfy a real product-proof requirement;
- a flat real UI may set scene lighting to `NOT_APPLICABLE`;
- campaign lighting may not introduce unapproved neon/glow/relighting.

### 4. First generation could be mistaken for final design

Resolved by the structured hero-generation contract and canonical sequence:

`RAW → SELECT → REMOVE EXCESS → REFINE → DETERMINISTIC TYPE/BRAND/CTA → QUALITY PASS`.

Generated critical text/logo is explicitly forbidden.

### 5. Representative approval alone did not define cross-size grammar

Resolved by `campaign-design-system.json`, which freezes:
- grid;
- headline/offer/CTA behavior;
- brand anchor;
- hero/crop language;
- background/accent system;
- lighting system;
- whitespace;
- per-layout-family adaptation;
- forbidden patterns.

### 6. Semantic identity could disappear between preproduction and rendering

Resolved by propagating and validating:
- preproduction SHA;
- campaign-design-system ID/SHA;
- idea-architecture ID;
- visual-character ID;
- lighting-intent ID;
- art-direction ID;
- creative-contract SHA.

This identity now appears in render specs and output manifest and is checked again before review dispatch.

### 7. Review previously focused mostly on surface quality

Resolved by mandatory review checks for:
- idea fidelity;
- emotional fidelity;
- visual-character fidelity;
- campaign-design-system fidelity;
- lighting-intent fidelity;
plus prior brand/category/asset/hierarchy/type/crop/contrast/CTA checks.

Pack review applies those checks across sizes.

## Real acceptance regressions

### REAL-01

Rejected Work output exposed:
- premature rendering before research;
- nearly identical direction grammar;
- generic/toy-like imagery;
- weak professional B2B signal.

### REAL-02

Improved Work direction exposed:
- unapproved CTA drift;
- ambiguous brand display identity;
- need for fail-closed real UI/logo asset readiness.

Both remain regression requirements.

## Remaining independent validation

This controller review does **not** close:
- fresh visual-model calibration against hidden-key evals;
- genuinely independent repository/PR review;
- final user acceptance of a real high-fidelity representative and multi-size pack.

Do not call `RUN_RIGOR=FULL` until the applicable independent gates are actually executed.
