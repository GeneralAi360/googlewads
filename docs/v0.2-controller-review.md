# v0.2 Controller Repository Review

Review type: **controller-owned hardening review, not independent approval**.

Compared scope: `main` → `dev/performance-banner-designer-v0.2`.

The branch is 96+ commits ahead of the original `main` foundation and contains the complete v0.2 candidate pipeline. This review checks internal consistency, fail-closed behavior, source-of-truth boundaries, documentation claims, and whether deterministic tests cover the implemented contracts. It must not be counted as the independent repository review required for `RUN_RIGOR=FULL`.

## Findings reconciled during the review

### CR-01 — Art direction existed in prose but was not frozen as production identity

**Risk:** a banner worker could preserve copy/brand while silently switching to another visual language.

**Fix:** approved creative contracts now require an `art_direction` object with `art_direction_id`, visual thesis, mode and selection provenance. The ID is validated during creative freeze, propagated into each render spec, checked by the binding validator and pack runner, and emitted in the final manifest.

**Status:** FIXED.

### CR-02 — Runtime lighting target selectors exceeded JSON-schema vocabulary

**Risk:** runtime could correctly accept `target_slot` / `target_slots` for `hero_edge_glow` and `text_plate` while a schema-aware controller rejected the same valid spec.

**Fix:** `banner-render-spec.schema.json` now exposes the runtime selectors; regression tests cover schema/runtime alignment.

**Status:** FIXED.

### CR-03 — Design-QA index was hash-checked but diagnostic file existence was not fail-closed at reviewer dispatch

**Risk:** a reviewer task could be created with a stale/missing grayscale, squint or thumbnail path.

**Fix:** `materialize_review_jobs.py` now validates source hash, exact actual-output path and existence of every required diagnostic view before materializing a review task.

**Status:** FIXED.

### CR-04 — Review checks did not encode the newly adopted craft diagnostics

**Risk:** thumbnail/glance, grayscale, squint and anti-template review could remain optional prose rather than machine-readable review state.

**Fix:** banner-review and pack-review schemas now allow the corresponding diagnostic/design-grammar checks; review materializer tasks explicitly request them.

**Status:** FIXED.

### CR-05 — Canonical E2E stopped at technical manifest

**Risk:** tests could prove rendering/Google validity while not exercising art-direction freeze, creative binding or review-dispatch infrastructure.

**Fix:** the seven-format E2E now passes through creative + art-direction freeze/binding, real Google preflight, manifest/contact sheet, design-QA diagnostics and seven independent-review task files plus the pack-review task. It deliberately does not fabricate review reports.

**Status:** FIXED.

### CR-06 — README/roadmap described an older branch/test baseline

**Risk:** documentation understated or misrepresented the active release candidate.

**Fix:** documentation now names `dev/performance-banner-designer-v0.2`, describes the design-craft/art-direction/diagnostic review layers and reports the current verified test milestone.

**Status:** FIXED.

### CR-07 — Composite `banner-run.schema.json` represented an older architecture

**Risk:** two competing run source-of-truth models could encourage bypassing freeze/binding contracts.

**Fix:** the schema is now explicitly marked legacy compatibility and points to the canonical split v0.2 contracts. Its inline creative snapshot is aligned with `art_direction_id` and no longer presented as a production bypass.

**Status:** FIXED.

### CR-08 — SKILL-facing visual-eval materializer name did not match implementation filename

**Risk:** a controller following the documented calibration command could resolve a nonexistent path.

**Fix:** added canonical wrapper `scripts/materialize_visual_review_evals.py` delegating to the existing hidden-key implementation.

**Status:** FIXED.

## Deliberate design decisions reviewed

### Minimal pre-binding worker briefs

`materialize_banner_jobs.py` creates narrow routing/task shells before creative binding. Exact copy and frozen art-direction provenance are subsequently written into the job-local render spec, while the controller supplies the relevant frozen creative contract to the worker. The richer `assets/banner-task-brief-template.md` is a controller-facing template rather than a requirement to duplicate the entire run context into every early task file.

Decision: **KEEP**. Context minimization is preferable to duplicating broad state.

### Function-level development escape hatch

`render_banner_pack.render_pack()` can be called with creative binding disabled for narrow unit/development fixtures, while the production CLI requires frozen binding unless `--allow-unbound-creative` is explicitly supplied. Canonical SKILL flow uses the fail-closed CLI/production path.

Decision: **KEEP WITH EXPLICIT DEVELOPMENT LABEL**. Do not use the escape hatch for production completion claims.

### Diagnostic views are not delivery assets

Thumbnail, grayscale and squint artifacts exist only for visual diagnosis. They are hash-bound to the original output and may not replace actual-size review or be uploaded to Google.

Decision: **KEEP**.
