# v0.2 Release Gate

`dev/performance-banner-designer-v0.2` is an active release-candidate hardening branch, not a completed release.

## Real Work regression classes

Real acceptance has now produced seven permanent regression classes:

- `REAL-01` — premature rendering before enough category/competitor research; superficially different directions; generic/toy-like B2B imagery; insufficient professional category fit.
- `REAL-02` — stronger research-first direction still drifted into an unapproved CTA / ambiguous brand identity and correctly exposed the need for real product UI/logo assets.
- `REAL-03` — a correct production `NEEDS_ASSET` state was applied too early and incorrectly skipped IDEA / VISUAL_CHARACTER / Style Intelligence / attention / typography / LIGHTING_INTENT.
- `REAL-04` — the user clarified that the approval artifact must be the rendered visual concept itself, not a text-only art-direction description.
- `REAL-05` — production asset blockers still caused the system to show no actual visual concept to the user even after strategy had completed.
- `REAL-06` — the system designed the wrong commercial job (`IMPLEMENTATION_SERVICE` instead of Bitrix24 license purchase), treated an internal A2 recommendation as if it were a user lock, showed only one concept, and allowed a weak presentation-slide-like visual to reach the user.
- `REAL-07` — Work reported two `PRESENTATION_READY_DESIGN` passes while still in image generation and surfaced generic abstract blue/metal hero imagery. The visible artifact was a raw visual component rather than a complete banner composite with commercial message, CTA and brand anchor. This exposed both raw-asset/banner-role confusion and a pre-show review false positive.

## Canonical user-facing production path

The intended UX is now:

`QUESTIONS / INTAKE`
`→ EXACT COMMERCIAL JOB LOCK`
`→ RESEARCH / STRATEGY`
`→ FIRST-ROUND VISUAL EXPLORATION`
`→ GENERATE / SELECT COMPONENT ASSETS ONLY WHERE USEFUL`
`→ COMPOSE COMPLETE REPRESENTATIVE BANNERS`
`→ TWO FRESH EXACT-ARTIFACT PRE-SHOW REVIEWS`
`→ USER SELECTS A DIRECTION`
`→ REVISE / APPROVE SELECTED VISUAL`
`→ PRODUCTION ASSET COMPLETION IF NEEDED`
`→ PRODUCTION REPRESENTATIVE / FIDELITY`
`→ CAMPAIGN DESIGN SYSTEM`
`→ FULL PRODUCTION`
`→ GOOGLE TECHNICAL + POLICY PREFLIGHT`
`→ REVIEW / DELIVERY`

If the user explicitly locked a visual direction beforehand, the first-round exploration may use a single concept. An internal recommendation, Style Intelligence recommendation, category recommendation, prior Work recommendation, or reviewer preference is **not** a user lock.

## Commercial-job gate — REAL-06

Product identity, campaign objective, CTA, and the exact commercial transaction/service job are separate facts.

For Bitrix24, these are materially different jobs:

- `NEW_LICENSE_PURCHASE`;
- `LICENSE_RENEWAL`;
- `PURCHASE_OR_RENEWAL`;
- `IMPLEMENTATION_SERVICE`;
- `CONSULTATION`.

Canonical artifacts:

- `references/commercial-job-and-concept-exploration.md`;
- `schemas/campaign-commercial-job.schema.json`;
- `scripts/validate_campaign_commercial_job.py`.

A material commercial-job change returns `COMMERCIAL_JOB_CHANGED` and invalidates meaning-dependent downstream artifacts rather than preserving the old design with a copy edit.

For `PURCHASE_OR_RENEWAL`, the controller must resolve whether purchase/renewal are deliberately `COMBINED` or represented as `SEPARATE_VARIANTS`.

## Visual exploration gate — REAL-06

`deliverables.concept_count` means the number of final creative concepts to be produced/scaled. It does **not** mean the number of alternatives the user sees before choosing the visual system.

A campaign may therefore have:

- final `concept_count = 1`;
- first-round `visual_exploration_count = 3`.

Unless explicit `USER_LOCKED` evidence exists, the first visual round must use `EXPLORE_3` and show exactly three materially different rendered concepts in the same representative size.

Canonical artifacts:

- `schemas/visual-concept-set.schema.json`;
- `scripts/validate_visual_concept_set.py`.

Every pair of first-round concepts must differ on at least three of these axes:

1. hero logic;
2. composition system;
3. attention profile;
4. typography profile;
5. graphic device;
6. lighting language.

Palette swaps, crop changes, different button colors, or three versions of the same copy-left/image-right SaaS layout do not satisfy exploration.

## Raw hero asset != banner concept — REAL-07

Load `references/concept-composite-and-pre-show-quality.md` for every first-round visual exploration and every generated/hybrid hero path.

Explicit artifact roles now matter:

- `HERO_ASSET_CANDIDATE` — upstream component only;
- `BANNER_COMPOSITE` — the only valid user-facing visual-concept artifact.

A generated image, UI crop, photograph, illustration, texture, 3D object or visual device may be used inside a concept, but it cannot itself receive user visual-concept approval.

Every `visual-concept-preview.json` must now bind:

- `artifact_role = BANNER_COMPOSITE`;
- `render_stage = USER_FACING_CONCEPT_COMPOSITE`;
- composition method;
- primary message;
- commercial-job cue;
- CTA;
- brand anchor;
- raw generated asset paths;
- `raw_generated_asset_is_final_artifact = false`.

`validate_visual_concept_preview.py` now decodes the actual PNG/JPEG, checks real raster dimensions against the declared dimensions and rejects a raw generated asset path reused as the final concept artifact.

If image generation stalls or repeatedly produces low-value generic imagery, generation must be abandoned rather than blocking banner completion. Type-led, product-led, editorial or structural concepts remain valid alternatives.

## Two fresh exact-artifact pre-show reviews — REAL-07

A concept may receive `PRESENTATION_READY_DESIGN` only after the complete exact `BANNER_COMPOSITE` exists.

Canonical schema:

- `schemas/pre-show-visual-review.schema.json`.

Each first-round concept now requires exactly two review report files, bound to the same exact artifact SHA, with:

- `reviewed_by = ART_DIRECTOR_REVIEWER`;
- distinct `reviewer_context_id` values;
- `fresh_context = true`;
- `prior_review_verdict_visible = false`.

Both reports must provide visible-artifact evidence and PASS for:

- commercial-job fidelity;
- complete banner composite;
- primary-message visibility;
- CTA visibility/integration;
- brand-anchor visibility;
- hero semantic relevance;
- advertising impact;
- compositional confidence;
- typographic craft;
- visual polish;
- premium category bar;
- non-generic identity;
- ad-not-presentation-slide;
- small-format viability.

A bare PASS boolean or a review of a raw hero image is insufficient.

If either reviewer returns `REVISE_BEFORE_SHOW`, the concept must be revised internally before the user sees it.

This is still a quality-control contract, not a performance predictor.

## Production asset readiness versus visual concept visibility — REAL-03 / REAL-05

Production asset readiness and user concept visibility are separate concerns.

Production `NEEDS_ASSET` blocks final production representative / scale-out / final exact-artifact clearance / delivery-ready claims. It does not by itself block upstream strategy or a safe concept preview.

Safe preview modes remain:

- `PRODUCTION_ASSET`;
- `REFERENCE_ONLY_SURROGATE`;
- `LOW_RES_AUTHENTIC_SURROGATE`;
- `STRUCTURAL_PLACEHOLDER`;
- `TEXT_BRAND_PLACEHOLDER`.

Fake/generated product UI and fake/generated logos remain prohibited even in a preview.

A surrogate preview stays `approval_scope = VISUAL_SYSTEM_WITH_ASSET_SLOTS`, `production_asset_readiness = NEEDS_ASSET`, and `not_for_delivery = true`.

## Visual approval boundary — REAL-04 / REAL-05

The user approves what they can actually see. Written art direction is an internal production contract and cannot substitute for visual approval.

After the user selects one first-round concept:

- `APPROVE` binds the exact visible artifact/system;
- `REVISE` requires a new rendered version and another visual decision;
- `REJECT` returns to the smallest responsible upstream layer;
- if all first-round concepts are rejected, create a new materially different exploration set rather than cosmetic remixes.

After real asset substitution, fidelity `PASS` may continue without redundant second user approval; `MATERIAL_DRIFT` requires showing the changed production representative again.

## Google Ads policy acceptance gate

Before a real pack is called `Google-ready`, exact-artifact technical and policy evidence must pass for every final banner, including misleading-design, image/text quality, claims/qualifiers, real destination support, advertiser identity, affiliation/trademark context and applicable restricted-vertical/targeting requirements.

Local policy preflight never guarantees actual Google approval.
