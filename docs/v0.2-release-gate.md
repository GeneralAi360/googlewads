## Google Ads policy acceptance gate

A technically correct banner is not automatically policy-ready.

Before any final pack is called `Google-ready`, the real Work acceptance run must demonstrate:

- [ ] current English Google Advertising Policies are checked or the local snapshot is still fresh;
- [ ] every final banner has a hash-bound `GOOGLE_POLICY_REVIEWER` result;
- [ ] no misleading system-warning/dialog/menu/pseudo-control design;
- [ ] no download/install UI, misleading pseudo-interactions, segmented/multi-ad appearance or transparent-background image ad;
- [ ] image/text quality is policy-acceptable at actual size;
- [ ] material offer/price/proof/guarantee claims are verified;
- [ ] required qualifiers are preserved;
- [ ] final landing page accurately supports the advertised offer and CTA;
- [ ] destination working/domain/crawlability/target-geo/accessibility evidence is resolved;
- [ ] advertiser identity and any affiliation/partner claim are verified;
- [ ] third-party trademark use is either cleared in context or explicitly remains `TRADEMARK_REVIEW_REQUIRED`;
- [ ] restricted/sensitive vertical, certification and targeting-policy states are resolved when applicable;
- [ ] every banner report is `GOOGLE_POLICY_PREFLIGHT_PASS`;
- [ ] pack aggregation is `GOOGLE_POLICY_PREFLIGHT_PASS`;
- [ ] final local status is `GOOGLE_READY_PRECHECK_PASS`;
- [ ] delivery language still states that final Google review applies and approval is not guaranteed.

Any `GOOGLE_POLICY_PREFLIGHT_BLOCKED`, `GOOGLE_POLICY_PREFLIGHT_INCOMPLETE` or `POLICY_REVIEW_REQUIRED` blocks a Google-ready claim.

## Merge rule

Do not merge into `main` merely because deterministic CI is green.

Merge only when:
1. deterministic CI is green on the final head;
2. the real Work acceptance gates above pass;
3. the Google Ads policy acceptance gate passes on the real final test pack;
4. the user's additional style-example integration has been evaluated;
5. independent rigor gates are satisfied, **or** the user explicitly accepts degraded rigor;
6. the user explicitly approves merge.

Until then:
- deterministic engineering: `ACTIVE_HARDENING`;
- real user-acceptance validation: `RETEST_REQUIRED`;
- Google policy readiness: `REAL_PACK_VALIDATION_REQUIRED`;
- delivery/runtime rigor: `NOT_FULLY_VALIDATED`;
- merge: `BLOCKED_BY_RELEASE_GATE`.
