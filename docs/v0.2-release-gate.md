## Visual concept approval acceptance gate

Before any real full banner pack is produced:
- [ ] intake asks only the business/design questions necessary to create the campaign correctly;
- [ ] strategy is resolved internally before rendering;
- [ ] required assets are validated at the render boundary;
- [ ] one real high-fidelity visual concept is rendered, normally 300x250 unless another format is more representative;
- [ ] the user is shown the actual rendered image, not only a text description;
- [ ] the exact visual artifact is bound by SHA-256;
- [ ] user decision is explicitly captured as `APPROVE`, `REVISE`, or `REJECT`;
- [ ] only `APPROVE` may allow campaign-design-system freeze and scale-out;
- [ ] `REVISE` causes a new rendered version and a new approval cycle;
- [ ] `REJECT` returns to the smallest responsible upstream design/strategy layer;
- [ ] no full pack is produced before `VISUAL_CONCEPT_APPROVED`.

## Google Ads policy acceptance gate

Before a real pack is called `Google-ready`:
- [ ] current English Google Advertising Policies are checked or local snapshot is fresh;
- [ ] every final banner has an exact-SHA `GOOGLE_POLICY_REVIEWER` result;
- [ ] no misleading system/dialog/pseudo-control/download-install/pseudo-interaction/segmented/transparent-background issue;
- [ ] image/text quality is policy-acceptable;
- [ ] material claims and required qualifiers are verified;
- [ ] real landing page supports exact offer and CTA;
- [ ] destination working/domain/crawlability/geo/accessibility evidence is resolved;
- [ ] advertiser identity and affiliation claims are verified;
- [ ] trademark use is contextually resolved;
- [ ] restricted vertical/certification/targeting states are resolved when applicable;
- [ ] every report and pack aggregation is `GOOGLE_POLICY_PREFLIGHT_PASS`;
- [ ] final local status is `GOOGLE_READY_PRECHECK_PASS`;
- [ ] delivery still states final Google review applies and approval is not guaranteed.

Any `GOOGLE_POLICY_PREFLIGHT_BLOCKED`, `GOOGLE_POLICY_PREFLIGHT_INCOMPLETE`, or `POLICY_REVIEW_REQUIRED` blocks a Google-ready claim.

## Merge rule

Do not merge because deterministic CI is green alone.

Merge only after real Work acceptance, visual-concept user approval flow, real-pack Google policy acceptance, style-example evaluation, independent rigor (or explicit degraded-rigor acceptance), and explicit user approval.

Until then:
- deterministic engineering: `ACTIVE_HARDENING`;
- real user-acceptance validation: `RETEST_REQUIRED`;
- visual approval readiness: `REAL_VISUAL_CONCEPT_REQUIRED`;
- Google policy readiness: `REAL_PACK_VALIDATION_REQUIRED`;
- merge: `BLOCKED_BY_RELEASE_GATE`.
